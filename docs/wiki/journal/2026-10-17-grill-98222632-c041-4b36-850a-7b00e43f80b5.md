## Question 1

```text
Round: Pi migration: first Mac pass
Question: Should the first Mac pass only replace the model runtime, or also introduce resumable agent execution?
Description (Markdown source):
The Windows handoff recommends starting with pi-ai, but leaves Pi Durable unselected.

**Runtime replacement:** use pi-ai for ChatGPT authentication and model calls, remove the bundled Codex executable after verification, and retain the existing assistant actions, SQLite histories, queues and Retry-after-interruption behavior.

**Durable execution too:** adopt pi-durable as the execution engine and integrate its persisted tasks with the existing records, so eligible unfinished work can continue after restart. This adds recovery and migration work, including preventing repeated document edits. Its upstream API is experimental.

Both paths remain local, preserve your records and existing Codex sign-in, and keep the requested model, high reasoning and ChatGPT subscription requirement. Exact model access needs verification through the new connection; there will be no silent fallback.

Sources: [project handoff](https://github.com/rengwu/ununemploy/blob/169dca657a18b142fbcfabba2e965d9358c972c6/docs/wiki/journal/2026-10-18-pi-runtime-handoff.md), [Pi Durable](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md).
Recommendation: Replace the runtime with pi-ai first. This addresses the package-size goal while preserving established behavior; add Durable when resumable execution is a required product outcome.
Options: pi-ai first; preserve current recovery behavior (Recommended) / Include pi-durable and resumable execution in this pass
Selected: pi-ai first; preserve current recovery behavior (Recommended)
```
