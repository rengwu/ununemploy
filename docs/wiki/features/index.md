# Feature map

These records separate expected behavior from dated verification. Stable IDs identify the behavior; a historical pass applies only to the build and scenarios recorded.

| Feature ID | Record | Main entry point |
| --- | --- | --- |
| FEAT-desktop | [Native desktop app](desktop.md) | Finder / Spotlight |
| FEAT-job-inbox | [Job inbox and saved jobs](job-inbox.md) | Jobs / Saved |
| FEAT-discovery | [Discovery and sources](discovery.md) | Sources / Settings |
| FEAT-matching | [Matching and listing quality](matching.md) | Match / result filters |
| FEAT-profile | [User profile and evidence](profile.md) | User profile / assistant |
| FEAT-master-cv | [Master CV and legacy resumes](master-cv.md) | CV |
| FEAT-cover-letters | [Saved-job cover letters](cover-letters.md) | Saved → job → Cover letter |
| FEAT-assistant | [App-wide assistant](assistant.md) | Header assistant button |
| FEAT-jev | [Optional Jev assessment](jev.md) | Settings → Jev / Match |
| FEAT-documentation | [Project wiki](documentation.md) | README / offline reader |

The core journey is profile readiness → discovery → inspect/match → save → private cover-letter review/download. The master CV remains independently editable. See [shared setup](../verification/setup.md), [architecture](../reference/architecture.md) and [known limits](../reference/limitations.md).
