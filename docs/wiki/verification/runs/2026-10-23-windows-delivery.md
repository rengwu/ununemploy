# Compact Windows setup

## Scope and build

Implement and verify the approved smaller bundle and direct Windows installation for [FEAT-desktop](../../features/desktop.md), carrying the [onboarding repairs](2026-10-21-assistant-onboarding.md) into the installer. The user requested jstack work-until-grill. No consequential implementation choice remained unresolved; the work proceeded through local implementation and checks.

The published `v0.2.0-beta.7` was built from clean revision `125446e992552a774ec95718690a8b3bf8a3d865` on GitHub's Windows 2025 runner with Node 22.23.3, Go 1.26.5, pi-ai 1.3.0, Inno Setup 7.1.0 and installed Evergreen WebView2. Its [hosted workflow](https://github.com/rengwu/ununemploy/actions/runs/39853817046) passed and published the [prerelease](https://github.com/rengwu/ununemploy/releases/tag/v0.2.0-beta.7). The anonymous public download and SHA-256 check also passed. Live sign-in/original-document interpretation and missing-WebView2 provisioning remain untested, so the aggregate is **Untested**.

Earlier local checks used Windows 11 x64. Base revision `159bce03bd1b8f0f68c91a2b22e6b9d4135ccf64`, with dirty implementation identified by the [source manifest](../../evidence/2026-10-23-windows-delivery/source-manifest.json). Source manifest SHA-256: `06743fbb47e73eace5402ca1e3af0094519a9fa5764b1632a0a06ce7b4555149`. The [local installer metadata](../../evidence/2026-10-23-windows-delivery/local-release.json) records the prototype; [hosted metadata](../../evidence/2026-10-23-windows-delivery/hosted-release.json) identifies the final delivered artifact. The setup prototype was exercised again with a genuinely empty appdata directory: it opened signed out, with an empty profile and zero jobs. Its SQLite file also survived update and uninstall. Raw logs, generated synthetic documents and screenshots remain local under `.local-data/verification/`.

The installer checks use a temporary installation directory containing spaces, synthetic personal-data retention sentinel, no existing Inno registration and no Start menu icons. The native driver uses another isolated synthetic database with scheduling/inference disabled and only Windows system directories on PATH. No canonical user records or authentication are used.

## Failure investigation and limits

The first native PDF prototype rejected WebView2's initial in-memory data URL. The policy now permits only the exact first document navigation and blocks frames/subsequent navigation. Native and PDF isolation checks then passed. The fresh-appdata driver initially asserted authentication before the worker finished its startup check; it now waits for the reported state. One local build overlapped a setup compile and could not rename the previous output; the existing package remained intact. Build/compile steps must run sequentially, as in the release workflow.

The [first hosted run](https://github.com/rengwu/ununemploy/actions/runs/39834162496) failed while securing a fresh synthetic credential directory. PowerShell 7 passes its module search path through Node to Windows PowerShell 5.1, which can resolve incompatible modules; [Microsoft documents this inheritance behavior](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_psmodulepath#starting-windows-powershell-from-powershell-7). A local incompatible-module fixture reproduced the same credential-read failure. Fixed scripts now select the executing shell's system modules. The new regression, four existing credential/inference tests and TypeScript check pass locally.

The [second hosted run](https://github.com/rengwu/ununemploy/actions/runs/39835014232) at clean revision `8d79950` passed all 47 focused tests, Go tests, application build and setup compile. Setup installed in 56 seconds, but the empty installed application's authentication state was unavailable instead of signed out. The same packaged startup with a synthetic incompatible module path and minimal PATH passed locally. Revision `184b7d2` retains the permission error cause and adds diagnostics only for the empty installer-test fixture. Its [hosted diagnostic run](https://github.com/rengwu/ununemploy/actions/runs/39836656701) passed empty first run, interrupted-install rollback and upgrade, then exposed a short-path process-detection bug: `RUNNER~1` did not match the running executable's full path. The original unavailable-authentication event did not recur in that run; its precise cause remains unknown, so the next setup driver checks three separate empty data directories and retains failure diagnostics.

The [beta.2 run](https://github.com/rengwu/ununemploy/actions/runs/39838442482), revision `13af7ed`, passed three separate empty startups, rollback and upgrade. Its running-application refusal still failed because the executable path could itself use an alias. The expanded local regression launches the process through its short name; it reproduced the failure before the second fix and passes after it. Installer path checks now expand existing DOS short-name components on both sides before comparing installation, personal-data and running-process paths. All 12 installer tests pass locally, including the uninstaller's running-process refusal. The next tagged build is `v0.2.0-beta.3`; failed tags are retained unchanged. No checks were bypassed and no release was published by the failed attempts.

The [beta.3 run](https://github.com/rengwu/ununemploy/actions/runs/39839712256), clean revision `5974092479a746ebb2817878e5d4867f98f9f0fa`, passed the running-process guard, three empty startups, rollback and update. Installation took 48.87 seconds and update 11.68 seconds. Its installed native journey reached offline LaTeX and dirty-Quit cancellation, then timed out waiting for the Save As PDF. Publication did not run.

A local custom-TEMP/short-path fixture reproduced the download failure and exposed a separate compiler temporary-directory issue. The native launcher now resolves Windows' per-user LocalAppData known folder for the compiler's temporary root; isolation and cleanup remain intact. With that fix, diagnostic inspection found Save As had restored its default filename after the driver set the destination. The driver now activates the app, waits for the filename to remain set, and presses the actual Save button. The complete native journey then passed with the custom short-path TEMP, including the chosen PDF destination, attachment reading, LaTeX, letter PDF, backups, lifecycle and persistence. Diagnostic results remain local because they include fixture paths. The workflow now retains sanitized-fixture native failure diagnostics and runs independent PDF/install regressions even if the main journey fails. The next tagged build is beta.4; beta.3 remains unchanged.

The [beta.4 run](https://github.com/rengwu/ununemploy/actions/runs/39844767730), clean revision `795e53465ff7339f67017c03b2e539f562c5e618`, still failed the native download expectation. Unlike the earlier local timing failure, the dialog had closed; no destination file appeared. Independent PDF export/isolation and all 12 installer regressions passed on the hosted runner. Local native journeys also passed with redirected LocalAppData, short-name TEMP and a ten-second pause before choosing the download destination. The next diagnostic run adds test-only native save-path, completion and interruption observations; no release has yet been published.

The [native download trace](https://github.com/rengwu/ununemploy/actions/runs/39848338115), clean revision `7853efea65e3e7d38a4615a7f3e927b03b230ff3`, established that WebView2 completed the download successfully with interrupt reason zero. However, Save As returned the default Documents/resume.pdf location instead of the driver's requested fixture path. The driver had updated a legacy Edit control's displayed text without updating the shell dialog's filename model. This was a verification-driver failure, not a failed PDF export. The helper now checks foreground ownership/focus, types into the filename field using native keyboard input, verifies the field, and clicks Save. The next candidate is beta.5; the earlier tags remain unchanged.

The [beta.5 run](https://github.com/rengwu/ununemploy/actions/runs/39850537388), clean revision `3e07efb3fa6e392a213f07465b4231acb1f5bdba`, passed native Save As, attachment reading, letter PDF export, backup restoration and Close/reopen. It then failed the PID-only Quit cleanup assertion. The app window and instance metadata were gone, but the old check retained no identities for the reported surviving PIDs. Windows can reuse both process and parent IDs; [Microsoft documents why IDs alone cannot establish process identity](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process). The verifier now filters parent relationships by creation time, records process start times, and retains OS handles while waiting for those exact processes to exit. Any real survivors are reported by identity. The complete local native journey passes with this check; beta.6 will exercise it on the runner. No production lifecycle behavior was weakened or process check skipped.

The [beta.6 run](https://github.com/rengwu/ununemploy/actions/runs/39852273831), clean revision `f52c471f2096feb9f01a4a21cf637aca0552f67b`, identified the survivors as external Microsoft Edge processes. Its earlier scripted-navigation test had opened the user's default browser; local checks had missed the handoff because a browser was already running. The same handoff was reproduced locally after adding an origin-only trace in verification mode. Moving navigation into a page timer still reproduced it. Remote top-level navigation is now cancelled unconditionally. All existing external application links use target=_blank and retain the user-initiated new-window handler; the app does not own or terminate external user browsers. The native regression now checks both the retained app origin and the absence of external handoffs. The next candidate is beta.7.

The [beta.7 run](https://github.com/rengwu/ununemploy/actions/runs/39853817046), clean revision `125446e992552a774ec95718690a8b3bf8a3d865`, passed the complete installed journey, including the navigation regression, exact-process Quit and crash cleanup. Independent PDF isolation and all 12 installer regressions passed. It published at 2026-10-22 21:09:46 UTC (23 October in Malaysia). The subsequent anonymous download matched SHA-256 `ca85a36822d55fbe27e5833d8d3f65cdfca1ac2d5b308d82eb21234266f9b45c`. Earlier failed tags were retained unchanged; no check was bypassed to publish.

The setup is unsigned. Signing, ARM64, automatic/delta updates and macOS/Unraid runtime execution were not part of this Windows delivery. The existing alternate PDF implementation remains for non-Windows-desktop environments; no claim of cross-platform runtime verification is made. The hosted runner proves a fresh installed application with an existing WebView2 runtime, not a completed live ChatGPT conversation on the user's other Windows 11 machine.
